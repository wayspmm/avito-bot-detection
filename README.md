# Классификация ботов по событиям в суточном окне

Решение сделано в Python 3.12, зависимости лежат в requirements.txt. Ноутбук solution.ipynb нужно положить рядом с metric.py и папкой data из архива и выполнить все ячейки, после этого появится submission.csv. Случайность есть только в моделях, везде стоит random_state = 42, повторный запуск даёт побайтово тот же файл. Использованы только open-source библиотеки pandas, numpy, scikit-learn и LightGBM, метрика считается официальным metric.py

Сначала события приводятся в порядок. Полные дубликаты удалены: их около 1.5%, и у ботов и людей доля одинаковая. Колонка platform записана разными способами (WEB, Web, web, iphone, iOS и т.д.), её привожу к трём значениям: web, android, ios. Дальше оставляю только события с window_start_ts <= event_ts < window_end_ts. Около 12% событий лежат после конца окна и в признаки не попадают, так что всё считается по данным, доступным на момент окончания окна. События в файле перемешаны, поэтому они сортируются по времени внутри куки, и только потом считаются паузы. Пропуски отдельно не заполняю, потому что они осмысленные: у приложений нет координат курсора, у куки с одним событием нет пауз, у событий без объявления нет категории. Эти NaN остаются как есть, LightGBM обрабатывает их сам. Категориальные поля не кодирую напрямую. User-Agent имеет 148 уникальных строк, поэтому я разбираю его на флаги: headless, скриптовый клиент, приложение Авито, браузер, Linux, версия Chrome, несоответствие UA и платформы. Для item_category и item_location беру число уникальных значений на куку, так как распределения самих категорий у ботов и людей почти не отличаются.

Признаки строились из того, чем бот отличается от человека по данным. По времени: боты быстрее, медианная пауза у них 14 секунд против 47 у людей. Отсюда квантили и разброс пауз, энтропия ритма, доля быстрых пауз, число сессий и доля ночных событий. По типам событий: у ботов больше просмотров объявлений и выдачи и меньше избранного, логинов и фото. Поэтому считаются доли всех типов и доля просмотров с листанием фото. По контенту: число объявлений, категорий, запросов и глубина страниц выдачи. По курсору: у ботов он часто отсутствует, а 90-й перцентиль pointer_x около 1160 против 1730 у людей. Дополнительно используется возраст куки. Самый сильный эффект дали признаки по объявлениям, потому что сервисы сбора данных ходят по одним и тем же объявлениям. Первый такой признак — сколько других кук смотрели объявление за последние 7 дней. Второй — сглаженная доля ботов среди прошлых посетителей объявления. Она считается только по размеченным кукам из строго предыдущих дней, поэтому метка самой куки в неё не попадает.

Тест идёт позже train по времени, поэтому валидация тоже временная: три фолда, обучение на днях до границы и проверка на следующих трёх днях. Доля ботов в каждом фолде пересчитывается только по меткам обучающей части.

Результаты по метрике P@R≥0.7 на валидации (константа даёт около 0.08):

1. Baseline из quickstart (число событий и объявлений, RandomForest) - 0.095.
2. Поведенческие признаки, RandomForest - 0.676.
3. Поведенческие признаки, LightGBM - 0.755.
4. Плюс популярность объявлений - 0.825.
5. Плюс доля ботов по объявлениям - 0.903, ROC-AUC 0.945.

Ещё пробовала глобальную популярность по всем дням сразу: на валидации она даёт хороший результат, но смотрит в будущее относительно окна, поэтому отказалась. Из окон популярности 1, 3 и 7 дней лучшим оказалось 7. Финальная модель: LightGBM на всех признаках, обученная на всём train.

Код разбит на функции по группам признаков, нетривиальные места прокомментированы.

У решения есть ограничения. В каждом фолде всего 160-190 ботов, поэтому метрика скачет примерно на +-0.02. Для теста метки train отстают до 7 дней, а в валидации до 3. Я отдельно проверила сдвиг валидации на 4 дня вперёд: систематического падения не было (0.87 и 0.86 против 0.83 и 0.91 без сдвига), но на тесте результат может быть немного ниже. И самое главное: признаки по объявлениям работают, пока боты ходят по пересекающимся объявлениям. Если сервис сменит набор объявлений, качество упадёт примерно до уровня поведенческой модели, около 0.75.
